# Privacy and deployment handoff

## Application deletion and feedback

Settings edits optional context and versioned consent. Withdrawal blocks new external processing and publication after withdrawal; it cannot recall completed provider transfers. Records need separate deletion. Feedback stores target IDs, review association, helpful/unsupported choices and a bounded optional comment, never a duplicated message/result. It is removed with its target/account. Comments may themselves contain sensitive content; users are asked not to copy it.

Delete-all requires `DELETE ALL CONVERSATIONS`, CSRF and the active owner. Its transaction removes conversations, messages, requests and message feedback; in-flight replies cannot recreate deleted conversations. Selected report deletion additionally cascades its extraction jobs/results/reviews, analysis, report conversations and associated feedback.

Account deletion requires current-password reauthentication and `DELETE MY ACCOUNT`. A durable pending state is written before cleanup, optional context/consent cleared and sessions invalidated; pending accounts cannot log in or access APIs. A five-second bounded dispatcher retries removal of owned private originals using the existing recoverable report lifecycle. Only after reports/files are removed does a transaction delete remaining profile, conversation/message/request, extraction/review/analysis and feedback records. Failures keep the blocked pending account for recovery on restart; no email notification or public status endpoint is claimed. Local comparisons are transient dedicated fixtures and exports exist only in response memory, so neither creates stored health records. Provider copies and downloaded PDFs/backups remain outside this lifecycle.

Every publication transaction checks the active account and its target; account/consent writes fence concurrent processing. Reauthentication retries are rate-limited. Late session-store touch after deletion may log only `REQUEST_COMPLETION_FAILED`; a deleted account cannot authorize any session, even if an in-flight request recreates a session row. Such unusable rows expire by MongoDB TTL. Do not enable dependency debug logs in deployment; they may include session IDs.

## Configuration and topology

Use Node 24, `npm ci` in server/client, `npm run build` in client. Deploy the static `client/dist` behind HTTPS, routing same-origin `/api/` to Express on `127.0.0.1:5000` (or configured PORT). Vite's development proxy is not deployment routing. Express deliberately listens on loopback; exposing a container interface requires an explicit reviewed topology change. No automatic deployment/provisioning is performed.

Required private server variables: `MONGODB_URI` with an explicit application database and replica-set/Atlas transactions, long random hex `SESSION_SECRET`, exact `APP_ORIGIN=https://your-confirmed-host`, `NODE_ENV=production`, and optional PORT. Never commit/paste private values. MongoDB must be protected by authentication/network restrictions, with permissions for application writes, indexes and transactions. Back up both app/session database and private originals consistently.

Production cookies use `__Host-fyp.sid`, Secure, HttpOnly, SameSite=Lax, path /, no Domain, absolute eight-hour expiry. `TRUST_PROXY=loopback` is permitted only with a verified trusted reverse proxy on the same host; block external direct backend access and overwrite forwarded headers at that proxy. Other trust configurations are rejected. HTTPS origin and CSRF/Origin checks remain mandatory.

`REPORT_STORAGE_DIR` must be a durable private disk outside public/static directories, with restrictive service-account access and capacity monitoring. Local storage holds originals across restarts and refuses simultaneous processes sharing a root. It is not malware scanning. File delivery stays authenticated. Do not deploy ephemeral/container disk without a durable mounted volume. `EXPORT_FONT_PATH` is a server-controlled readable local font; Windows Arial/Linux DejaVu defaults are checked by export tests. Install/configure fonts and verify the deployment's languages. PDF tagging/complex bidirectional layout are not verified; original accessible HTML remains available.

`CHAT_PROVIDER=off` is the production default; explicit demo is rejected. Configured real chat/symptoms require `CHAT_PROVIDER=fastapi`, a confirmed reachable `AI_SERVICE_URL` origin and privately exchanged `AI_INTERNAL_KEY`. Real extraction requires `EXTRACTION_PROVIDER=fastapi` with the same service configuration. No browser AI credentials or unconfirmed destination is used. Require TLS/private trusted transport appropriate to the topology; HTTP configuration alone does not secure a remote service. `EXTRACTION_DEMO_ENABLED` must be false in production. Review exact timeout/byte/count/pixel variables in server/.env.example. Real reviewed analysis/report chat/comparison/doctor-summary remain unavailable pending their contracts.

## Readiness, recovery and operational limits

`/api/health` is process liveness, `/api/ready` checks the Mongo connection/ping; readiness does not certify AI reachability, font availability or disk health. Startup initializes indexes/transactions/private storage and does initial report reconciliation. Graceful SIGINT/SIGTERM stops HTTP, dispatchers/storage/session/database; a ten-second shutdown deadline can interrupt processing, so persisted leases and pending deletion state are recovery inputs.

Extraction stale attempts fail as interrupted instead of automatically replaying providers; retry is explicit with a new attempt UUID. Synthetic queued analysis resumes locally, expired running work fails, cancelled/stale revisions cannot publish. Pending account deletion retries files and database cleanup. Monitor stale uploading/deleting records and storage capacity without logging content. Back up before maintenance; test recovery on synthetic clones.

Single-process limitations: local files, storage-root locking, in-process rate/concurrency limits and background dispatchers. Limits reset on restart and are not distributed. Multiple replicas require a shared private storage/service design, distributed limits/leases and coordinated workers; this checkpoint does not claim that architecture. PDF rendering is bounded by reviewed row/text limits and two active exports; font shaping remains CPU work in-process. Chat retries are idempotent locally, but a provider timeout does not guarantee provider cancellation or prevent repeated provider inference after an explicit retry.

## Backup and restore procedure

1. Stop writes/dispatchers cleanly and take an encrypted MongoDB application/session snapshot plus a matching private-originals snapshot. Keep credentials in an approved private mechanism rather than terminal command history. Record snapshot time and application commit/configuration without secrets.
2. Enforce a documented retention/access policy for backups and track deletions that occurred after each backup. Application live deletion cannot erase independently retained backups.
3. Restore only to an isolated, non-public environment first, using compatible MongoDB transaction topology and private disk permissions. Do not reuse live storage-root locks or serve restored files publicly.
4. Before enabling access, invalidate restored sessions, reconcile post-snapshot deletion requests, inspect pending account/report deletion, let cleanup/recovery complete and verify original-file metadata/hash associations. A pre-deletion backup can otherwise resurrect removed accounts/data; reconciliation requires operator-held deletion records under a defined retention policy, not an application guarantee.
5. Verify health/readiness, auth/CSRF/ownership, synthetic upload/delete, reviewed export/font and interrupted jobs before enabling HTTPS traffic. Record the restore exercise. Unknown third-party retention and disaster-recovery guarantees remain external responsibilities.

## Security review scope and limits

Tests cover authentication/session restoration/fixation/expiry, cross-user resource denial, CSRF/Origin and rates, strict bounded validation, literal metadata search, immutable conversation bindings, UUID reconciliation, stale revision fencing, upload type/path/size safeguards, deletion interruption/late jobs and private exports. React renders text, no unsafe generated HTML. Source URLs are not fetched; current supplied schemas expose no citations. AI destinations and font paths are server controlled, redirects refused. Future citations must validate HTTP/HTTPS without credentials and never become fetch destinations. No compliance/penetration-test/clinical certification is claimed. Email verification, password reset, malware scanning, provider retention/cancellation and live clinical evaluation are not implemented.
