# Optional profile, consent and configured chat

GET/PUT `/api/account` reads/updates only the signed-in account. PUT requires `{name,healthContext:{medications,allergies,conditions},consent:{chat,reports,profile,noticeVersion:"fyp-ai-v1"},expectedVersion}`. Context is optional null or text up to 500 characters; display name is 1–80. Missing data is unknown. No age/DOB is collected because no agreed backend age mapping justifies it. Settings use optimistic concurrency and record decision time/notice version. Clearing context is separate from withdrawing processing permissions; withdrawal blocks new transfers/publication and does not recall provider copies or delete local records. No compliance claim is made.

`CHAT_PROVIDER=demo` is the development default. Production defaults to `off` and rejects explicit demo; configured `fastapi` is required for real replies. Explicit `fastapi` requires exact server-controlled AI_SERVICE_URL and privately configured AI_INTERNAL_KEY. Chat sends the current message, an owner-derived conversation ID, and at most three complete previous exchanges (six messages, each truncated to 2000 characters). It never sends the optional profile automatically. X-Internal-Key stays server-side; redirects are rejected; response limit 64 KiB; deadline 20 seconds; concurrency two. Source fields map from checked-in ChatResponse: reply, suggested_follow_ups, urgency_level, disclaimer. Development fallback reported by the provider is rejected rather than substituted as a live model answer. Model/prompt version and citations are absent and not invented. Chat consent is enforced before reservation/transfer and again transactionally before publication. Existing UUID ordering/retry fences remain. Streaming is unavailable because the contract is non-streaming. Client cancellation stops waiting; remote completion/cancellation remains unknown.

POST `/api/symptoms` maps symptoms, duration, severity and additional_notes to the supplied `/api/symptoms/assess` endpoint. All optional inputs may be null. Up to ten concerns of 200 characters, other fields up to 500. Authentication, CSRF, consent, rate limits and bounded transport apply. It displays provider urgency/escalation without frontend triage rules and treats causes as possibilities. This endpoint has an unlabelled Python fallback; the interface explicitly says model/fallback provenance is not supplied, and live clinical evaluation is not claimed. No symptom fixtures are attached to arbitrary users.

Profile sharing remains disabled pending an agreed patient_context mapping; its saved permission is not a transmission. Service destinations cannot be supplied by browser bodies. Real chat/symptom verification requires a reachable configured provider and synthetic end-to-end tests; no live inference has been verified here.
